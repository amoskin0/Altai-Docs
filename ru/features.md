# Возможности и ограничения

[Содержание](../README.md#русский) · [English](../en/features.md)

## Реализовано

| Область | Текущее поведение |
| --- | --- |
| Исходный текст | `.alt`, строгий UTF-8, необязательный начальный BOM, LF/CRLF, регистрозависимые имена, комментарии `//` |
| Привязки | Изменяемые `var`; константные int64/bool через `const`; присваивание только существующим именам; фиксированные выводимые типы; лексические области без затенения видимых имён |
| Арифметика | Десятичные литералы int64, проверяемые `+ - * / %`, унарные знаки, проверяемые составные присваивания |
| Логика | bool, `!`, сокращённые `&&`/`||`, строгое равенство и знаковые целочисленные сравнения |
| Управление | `if`/`else if`/`else`, `while`, фигурные скобки, необязательная группировка условий |
| Функции | `fn` уровня файла, явные типы int64/bool/bytes/buffer/result/status, неизменяемые параметры по значению, опережающие вызовы, `return`, проверка путей возврата |
| Байты | Неизменяемые bytes, изменяемые buffer, len, проверяемый индекс, read_file, snapshot и обязательный match для result/status |
| Вывод | `print(expression)` для int64/bool или строкового литерала с добавлением одного LF |
| Инструменты | Просмотр токенов и дерева, статическая проверка, интерпретация, собственный генератор машинного кода Windows x86-64 |
| Диагностика | Позиции, фрагменты и подсказки статических ошибок, стабильные коды, явные ошибки арифметики и границ при исполнении |

Сгенерированная программа является отдельным консольным файлом Windows. Текущий компилятор реализован на C11 и не собирает себя на Altai. Генератор непосредственно создаёт AMD64/PE без языкового бэкенда LLVM, промежуточного C или внешнего ассемблера и линковщика при компиляции `.alt`. Сборка самого компилятора всё ещё требует начального набора инструментов; сгенерированные программы зависят от системных API Windows.

## Пределы

| Ресурс | Предел |
| --- | --- |
| Все статические привязки, включая параметры и все объявления | 256 |
| Функции | 64 |
| Параметры или аргументы одного вызова | 16 |
| Активные блоки if/while на тело | 64 |
| Глубина групп, вызовов, индексов и унарных операторов выражения | 128 |
| Одновременно живые постфиксные операнды | 128 |
| Совокупная модель стека вызовов машинного кода | 64 КиБ |

У циклов нет фиксированного предела итераций; каждая итерация не расходует новую ячейку привязки. Каждый кадр машинного кода меньше 4096 байтов и затрагивается при входе. Предел стека является моделью ресурсов сгенерированного кода, а не измерением точного расхода стека интерпретатора. Правила подсчёта и ошибок находятся в [спецификации](specification.md).

## Не реализовано

Числа с плавающей точкой, строковые переменные, массивы, срезы, изменение и равенство bytes, `for`, `break`, `continue`, рекурсия, функции void, вызовы с отброшенным результатом, модули, пакеты, замыкания, перегрузки, интерфейсы внешних функций и общая модель памяти не реализованы. В этом подмножестве нет браузерных API или универсальных прикладных фреймворков. Генерация машинного кода Linux/macOS не реализована.

Написанные на Altai классификаторы байтов являются вспомогательными функциями; полная проверка исходного текста, выделение токенов и хранилище декодированных строк остаются в реализации компилятора. Байтовых литералов только для чтения недостаточно для полного лексера или сборки компилятора на собственном языке.

## Динамическая память и файловый доступ

Реализованы `read_file`, `buffer`, `append_byte`, `snapshot`, `result<bytes>`, `result<buffer>` и `status`. Память освобождается автоматически; снимки независимы от дальнейших изменений буфера.

Лимиты: 16 МиБ на объект, 4096 живых объектов, 64 МиБ дескрипторов и ёмкости данных с учётом старого и нового хранилища при росте. Эти лимиты не ограничивают память компилятора, всю RSS, число итераций или время ожидания файлового ввода. Программа имеет файловые права запустившей её учётной записи; песочница не реализована.
