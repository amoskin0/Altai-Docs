# Машинный код и целевые платформы

[Содержание](../README.md#русский) · [English](../en/native.md)

`altai build source.alt program.exe` создаёт консольный исполняемый файл PE32+ AMD64. Статическая проверка и вычисление констант заканчиваются до создания файла. Обычные инструкции компилируются, а не исполняются сборщиком. Полученный файл работает без исходника, инструмента Altai и компилятора C.

## Целевые платформы

```text
altai build --target windows-x86_64 source.alt program.exe
altai targets
```

| Цель | Формат | ABI | Генерация |
| --- | --- | --- | --- |
| windows-x86_64 | PE32+ | Microsoft x64 | Реализована |
| windows-aarch64 | PE32+ | Windows ARM64 | Не поддерживается |
| linux-x86_64 | ELF64 | System V AMD64 | Не поддерживается |
| linux-aarch64 | ELF64 | AAPCS64 | Не поддерживается |
| macos-x86_64 | Mach-O 64 | Darwin x86-64 | Не поддерживается |
| macos-aarch64 | Mach-O 64 | Darwin ARM64 | Не поддерживается |

Реестр целей разделяет ОС, архитектуру, формат файла и соглашение вызовов. Цель не выводится из имени выходного файла. Неизвестные и неподдерживаемые цели отклоняются до создания выхода. Значение по умолчанию соответствует платформе компилятора; выбор цели не меняет язык. Переносимость самого компилятора и поддержка сгенерированных программ различаются. Кросс-сборка компилятора не подтверждает его исполнение на той платформе; Windows PE не является исполняемым файлом Linux/macOS.

## Контракт исполнения

Машинный код сохраняет определённые [спецификацией](specification.md) проверки арифметики, строгие типы, порядок эффектов слева направо, сокращённую логику, вызовы функций, циклы и диагностику времени исполнения. Сборщик не выполняет заранее обычную литеральную арифметику и индексирование байтов. Все ветви и тела статически проверяются; эффекты времени исполнения имеют только достигнутые операции.

Литералы bytes хранятся в программе без выделения полезных данных в куче. Динамические bytes и buffer используют собственный сгенерированный механизм подсчёта ссылок; аргументы, возвраты, присваивания и выход из областей сохраняют владение. Присваивание буфера разделяет содержимое, snapshot создаёт независимую копию. Индекс проверяется до чтения и возвращает int64 от 0 до 255.

Циклы повторно используют ограниченное хранилище без роста стека на каждой итерации. Проверка отклоняет рекурсию и ограничивает совокупную модель стека величиной 64 КиБ, включая основной код, вызываемые функции, адреса возврата и вспомогательную функцию вывода. Каждый кадр меньше 4096 байтов и затрагивается при входе. Это не общая система управления памятью и не утверждение о невозможности любых дефектов.

Исполняемый файл использует системные API KERNEL32.dll. Он содержит метаданные раскрутки стека; код и неизменяемые данные имеют раздельные права, секций с одновременным разрешением записи и исполнения нет. Включены NX, ASLR и виртуальная адресация с высокой энтропией. Эти свойства не устраняют зависимости от ОС и процессора и не доказывают полную безопасность. Для `.alt` используется собственный генератор без языкового бэкенда LLVM, промежуточного C и внешнего ассемблера или линковщика.

## Вывод и ошибки

Аргументы вывода вычисляются до обращения к stdout. Успешный интерпретируемый вывод сбрасывает буфер. Предыдущий успешный вывод сохраняется при поздней арифметической ошибке или выходе за границы. Интерпретатор и машинная программа используют одинаковые точные сообщения A0401/A0402/A0403 и коды завершения из [справочника команд](cli.md#коды-завершения). Ошибка stdout завершает программу кодом 2; неудачная диагностика времени исполнения сохраняет код 3.

В Windows сборка записывает новый временный файл рядом с назначением, сбрасывает данные, закрывает файл и публикует его без замены назначения. Существующий выходной файл, исходник и жёсткие ссылки на него отклоняются. При ошибке предпринимается очистка; сбои диска, питания и файловой системы могут её предотвратить, абсолютная устойчивость сохранения не гарантируется. Родительский каталог должен существовать и быть доступен для записи.

Запись выхода POSIX не проверялась исполнением на Linux/macOS в текущей среде проверки на Windows. Она требует доверенного родительского каталога и не гарантирует fsync каталога или устойчивость к аварийному завершению. Это не добавляет генерацию машинного кода для Linux/macOS.

## Динамическое исполнение

Файловый ввод, буферы, рост и снимки выполняются собственным машинным кодом с автоматическим освобождением памяти. Скалярные программы и литералы сохраняют четыре импорта KERNEL32.dll. Динамические программы дополнительно используют GetProcessHeap, HeapAlloc, HeapFree, CreateFileW, ReadFile, CloseHandle, MultiByteToWideChar и GetLastError.

Лимиты: 16 МиБ на объект, 4096 объектов и 64 МиБ управляемой ёмкости с учётом пика роста. Преобразование пути может потребовать ещё до 65534 байт. Лимиты не относятся ко всей RSS, исходникам компилятора, числу итераций или времени ожидания ввода. Пути используют рабочий каталог и права ОС, без песочницы. Стек динамических программ учитывает 352 байта для двух вложенных вспомогательных кадров по 168 байт и адресов возврата.
