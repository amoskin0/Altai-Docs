# Спецификация языка Altai

## Исходный текст и токены

Файлы исходного кода имеют расширение `.alt` и используют строгую кодировку UTF-8. В начале допускается один BOM: он занимает байты, но не столбец исходного текста. Другие символы U+FEFF не отбрасываются. Сначала проверяется весь вход на корректность UTF-8, затем все символы CR, затем лексическая структура. Одиночный CR недопустим везде, включая строки и комментарии. LF и CRLF увеличивают номер строки на один. Строки и столбцы нумеруются с единицы; столбцы считают скалярные значения Unicode, табуляция занимает один столбец.

Диапазоны токенов `[start, end)` задаются в байтах, начинаются с нуля и не включают правую границу. Конечный токен имеет пустой диапазон на длине входа и позицию после последнего скалярного значения. После завершающего LF/CRLF он находится в первом столбце следующей строки.

Вне строк и комментариев пробельными символами являются пробел ASCII, табуляция, LF и CRLF. `//` начинает комментарий до физического перевода строки или конца входа. Блочные комментарии не поддерживаются. Имя начинается с буквы ASCII, русской кириллической буквы, включая U+0401/U+0451, или `_`; далее также допускаются цифры ASCII. Регистр учитывается, нормализация имён не выполняется. Другие буквы Unicode и комбинируемые знаки в именах не поддерживаются. Визуально похожие латинские и кириллические буквы различаются.

`const`, `var`, `true`, `false`, `if`, `else`, `while`, `fn`, `return` и `match` являются зарезервированными ключевыми словами. `print`, `bytes`, `len`, `read_file`, `buffer`, `append_byte` и `snapshot` являются зарезервированными встроенными именами и не могут объявляться пользователем. `ok`/`err` и имена типов контекстные. `let`, `Var`, `variable` и прежние локализованные имена являются обычными пользовательскими именами, а не формами объявления или псевдонимами. Числовые токены содержат цифры ASCII. Начальные нули не меняют десятичную систему счисления. Суффиксы, разделители, экспоненты и дробные литералы не поддерживаются. `->`, `&&`, `||`, двухсимвольные сравнения и составные присваивания являются неделимыми токенами; `:` отделяет имя параметра функции от типа. Эти символы допустимы только в соответствующих грамматических контекстах. Прежнее объявление через `:=` отклоняется.

Строки заключаются в двойные кавычки. Допустимы escape-последовательности `\"`, `\\`, `\n`, `\r` и `\t`. Неэкранированные LF, CR, управляющие символы C0/C1 и U+007F отклоняются. Экранированный CR является данными значения, а не переводом строки исходного текста. U+2028/U+2029 допускаются как строковые данные. Значения содержат декодированные байты UTF-8. Escape-последовательности для NUL нет.

## Грамматика

```text
program     = { NEWLINE | statement | function } END
statement   = (simple | conditional | loop | matching | returning) terminator
simple      = ("var" | "const") NAME "=" expression
            | NAME assignment expression
            | "print" "(" expression ")"
assignment  = "=" | "+=" | "-=" | "*=" | "/=" | "%="
conditional = "if" expression lines block
              [ lines "else" lines (conditional | block) ]
loop        = "while" expression lines block
function    = "fn" NAME "(" [ parameters ] ")" "->" type lines block terminator
parameters  = NAME ":" type { "," NAME ":" type }
type        = "int64" | "bool" | "bytes" | "buffer" | "status"
            | "result" "<" ("bytes" | "buffer") ">"
matching    = "match" expression lines "{" lines success lines
              "err" "(" NAME ")" lines block lines "}"
success     = "ok" "(" NAME ")" lines block | "ok" lines block
returning   = "return" expression
block       = "{" { NEWLINE | statement } "}"
lines       = { NEWLINE }
expression  = disjunction
disjunction = conjunction { "||" conjunction }
conjunction = equality { "&&" equality }
equality    = ordering { ("==" | "!=") ordering }
ordering    = sum { ("<" | "<=" | ">" | ">=") sum }
sum         = product { ("+" | "-") product }
product     = prefix { ("*" | "/" | "%") prefix }
prefix      = ("+" | "-" | "!") prefix | postfix
postfix     = primary { "[" expression "]" }
primary     = NUMBER | STRING | NAME | "true" | "false"
            | NAME "(" [ expression { "," expression } ] ")"
            | "(" expression ")"
```

Для читаемости грамматика не показывает обработку переводов строки внутри выражений. Внутри скобок выражений, вызовов или индексов переводы строки являются пробельными символами. Вне открытых скобок перевод строки перед `[` завершает законченную инструкцию. Вне них перевод строки сразу после бинарного оператора продолжает незаконченное выражение, а перед оператором завершает инструкцию. Например:

```text
var total = 100 +
    20 +
    5
print(total)
```

Результат: `125`. Унарный префикс сам по себе не разрешает перевод строки вне группировки. Оператор присваивания тоже: инициализатор или правая часть присваивания начинаются на той же строке, что `=` либо `+= -= *= /= %=`, если открывающая круглая скобка не стоит на этой строке. Имя параметра, `:` и тип находятся на одной строке; то же относится к `->` и типу результата. Комментарий может завершать строку после бинарного оператора, продолжающего выражение. Заголовок if/while/функции может отделяться от открывающей фигурной скобки переводами строки. В примерах скобка стоит на строке заголовка; команды форматирования нет.

Терминатор поглощает перевод строки либо распознаёт непосредственно следующую закрывающую фигурную скобку или конечный токен, не поглощая их. Пустые строки, комментарии и отсутствие завершающего перевода строки допустимы. Закрывающая фигурная скобка завершает последнюю инструкцию блока, поэтому блок может быть записан в одну строку. После законченного условия или цикла перед следующей инструкцией всё равно нужны перевод строки, конец файла или закрывающая скобка внешнего блока. Точка с запятой распознаётся для диагностики, но отклоняется грамматикой.

Вызовы всегда используют круглые скобки; пробел перед `(` допустим. `print(1 + 2)` выводит `3`; `print 1 + 2` и `print(1 + 2) * 3` отклоняются. Вывод принимает ровно один аргумент, не может вкладываться в выражение и не имеет используемого результата. Скобки вызова учитываются в глубине выражения; скобки сигнатуры функции не учитываются. Отдельные инструкции вызова с отброшенным возвращаемым значением не поддерживаются.

## Имена и типы

```text
const quantity = 3
var price = 120
price = price + 5
print(price * quantity)
```

`var name = expression` объявляет новое изменяемое значение с обязательной инициализацией. `name = expression` только присваивает уже существующей видимой изменяемой привязке; новое имя не объявляется. Неизвестное имя назначения даёт A0301, поэтому опечатка не создаёт другую привязку молча. При проверке имён и типов ошибки имени назначения предшествуют семантическим ошибкам правого выражения. Полная лексическая проверка и синтаксический разбор всего входа всё равно заканчиваются до этого этапа.

Имя становится видимым только после инициализатора: `var x = x + 1` даёт A0301, а `var x = 1` с последующим `x = x + 1` допустимы. `var` и `const` не могут повторно объявлять или затенять видимую привязку; повторы и встроенные имена дают A0302. Объявления без инициализатора, явные аннотации типа привязки и `var name := expression` не поддерживаются.

`const name = expression` объявляет неизменяемую константу, вычисляемую при проверке или сборке. Допустимы целочисленные и логические литералы, более ранние константы и поддерживаемые скалярные операторы. Вызовы и привязки времени исполнения, включая неизменяемые параметры функций, запрещены даже в пропущенном операнде сокращённого логического вычисления (A0306). Некорректная арифметика в вычисляемом операнде тоже даёт A0306; арифметика в пропущенном операнде не выполняется. Повторное объявление видимого имени даёт A0302; присваивание константе даёт A0305. Псевдонима `:=` и объявления неизменяемой привязки времени исполнения через `let` нет.

Типизация статическая и строгая. Доступны типы `int64`, `bool`, неизменяемые `bytes`, изменяемые `buffer`, `result<bytes>`, `result<buffer>` и `status`. Тип локальной привязки или привязки уровня файла выводится при объявлении и сохраняется при присваиваниях; типы параметров и результата функции задаются явно. Строковые инициализаторы и присваивания дают A0303. Неявных преобразований, явных аннотаций типа привязки, других числовых типов, строковых переменных и констант нет. Файл и каждый блок в фигурных скобках имеют лексическую область видимости без опережающей видимости и затенения видимых имён. Лимит привязок расходуют новые объявления, параметры и привязки ветвей match.

Ошибки: A0301: неизвестное имя; A0302: повторное или зарезервированное объявление; A0303: ошибка типа; A0304: литерал вне диапазона; A0305: присваивание неизменяемой привязке; A0306: недопустимый инициализатор константы. `print (("text"))` допустим; строковая арифметика и строковые объявления являются ошибками типа.

Составные присваивания `+= -= *= /= %=` требуют существующего изменяемого назначения int64 и правой части int64. Они никогда не объявляют привязку и не работают с bool. Ошибки имени и изменяемости назначения предшествуют семантическим ошибкам правой части. При исполнении сначала читается старое значение назначения, затем правая часть вычисляется один раз, после чего сохраняется результат проверяемой арифметики. Ошибка правой части или арифметическая ошибка предотвращает сохранение и сохраняет прежние эффекты. Действуют те же правила переполнения, нулевого делителя и MIN/-1, что для обычной арифметики. Операторов инкремента и декремента нет.

## Арифметика и вывод

Диапазон: от -9223372036854775808 до 9223372036854775807. Модуль 9223372036854775808 допустим только непосредственно после унарного минуса, с возможным пробельным промежутком. `-(9223372036854775808)` содержит недопустимый положительный литерал. `--9223372036854775808` разбирается, но внешнее отрицание переполняется: это ошибка времени исполнения в обычной инструкции и A0306 в инициализаторе константы.

Приоритет от высшего к низшему: группировка, вызовы и индексация; унарные `+ - !`; `* / %`; `+ -`; сравнения порядка; равенство; `&&`; `||`. Бинарные операторы ассоциируются слева. Операнды и инструкции вычисляются слева направо. Деление отбрасывает дробную часть к нулю; остаток имеет знак делимого. Нулевой делитель даёт A0402. Переполнение сложения, вычитания, умножения, отрицания, MIN/-1 и MIN%-1 даёт A0401. Проверки предшествуют опасным машинным операциям; тихого циклического переноса значений нет.

Обычные выражения сохраняют проверки времени исполнения, даже если содержат только литералы. `check` и `build` принимают `print(1/0)`; исполнение заканчивается кодом 3. Исключение: инициализация константы. `const x = 1/0` является статической ошибкой до любого вывода.

`print(expression)` принимает одно целочисленное или логическое выражение либо строковый литерал и добавляет LF. Обязательные скобки аргумента могут содержать дополнительную группировку. Логические значения выводятся точно как `true` или `false`. Целые выводятся в десятичном виде без регионального форматирования. Аргумент вычисляется до обращения к stdout. Каждый успешный интерпретируемый вывод сбрасывает буфер. Поздняя ошибка исполнения сохраняет предыдущий вывод и предотвращает последующие инструкции.

## Байты только для чтения

```text
var data = bytes("abc")
print(len(data))
print(data[0])
```

Результат: `3` и `97`. `bytes` требует ровно одно выражение строкового литерала, включая литерал в группирующих скобках. Оно предоставляет декодированные байты UTF-8 литерала без завершающего нуля. `len` требует одно значение bytes или buffer и возвращает число байтов как int64. Символ вне ASCII может занимать несколько байтов. Существующие строковые escape-последовательности сохраняют смысл; создание bytes не добавляет новых последовательностей и не допускает некорректный UTF-8 или встроенный NUL в исходных литералах. Сырые данные файла и буферы могут содержать эти байтовые значения.

`base[index]` вычисляет основу один раз, затем индекс один раз, слева направо. Основа должна иметь тип bytes или buffer, индекс: int64. Результат имеет тип int64 и диапазон от 0 до 255 без знакового расширения. Отрицательный индекс и индекс, не меньший длины, дают A0403 до доступа к данным по индексу. Пустые значения имеют длину ноль; любой индекс для них ошибочен. Известные неверные индексы в обычных выражениях являются ошибками времени исполнения при достижении операции; `check` и `build` их не выполняют. Пропущенные ветви и операнды сокращённых логических вычислений не обращаются к данным, но все имена и типы статически проверяются.

Основой могут быть вызовы и группированные выражения: `get_data()[0]` и `(data)[0]`. Постфиксная индексация имеет приоритет выше унарных и бинарных операторов. Скобки каждого индекса учитываются в пределе глубины выражения и допускают внутренние переводы строки. Повторная индексация полученного int64 является ошибкой типа. Индексный доступ не может быть назначением присваивания.

Содержимое bytes неизменяемо. Привязке `var` типа bytes можно присвоить другое значение bytes; присваивания и вызовы функций сохраняют другие ссылки. Параметры bytes являются неизменяемыми привязками, а функции могут возвращать литералы, параметры или динамические bytes. Хранилище литерала существует всё время исполнения; динамические bytes действительны, пока на них ссылаются. Сгенерированные литералы находятся в данных программы только для чтения без выделения полезных данных в куче. Динамические значения используют описанный ниже управляемый runtime. Внутреннее представление не является публичным указателем или интерфейсом вызовов внешних функций.

`bytes`, `len`, `read_file`, `buffer`, `append_byte` и `snapshot` зарезервированы, включая объявления функций и параметров. Все вызовы запрещены в инициализаторах `const`. Для bytes/buffer нет равенства, сравнения порядка, арифметики, преобразования в указатель, срезов или вывода сырых байтов. `print(data)` является ошибкой типа; длину и индексированный байт можно вывести как int64.

## Файлы, буферы и результаты

| Операция | Параметры | Результат |
| --- | --- | --- |
| `read_file(path, limit)` | путь bytes, предел байтов int64 | `result<bytes>` |
| `buffer(limit)` | предел байтов int64 | `result<buffer>` |
| `append_byte(target, value)` | buffer, байт int64 от 0 до 255 | `status` |
| `snapshot(target)` | buffer | `result<bytes>` |

`read_file` возвращает сырые байты файла, включая все 256 значений. Содержимое не проверяется как UTF-8; BOM не удаляется, CRLF не преобразуется, завершающий ноль не добавляется, чтение не останавливается на NUL. Сам путь должен быть непустым корректным UTF-8 без NUL, не длиннее 32767 байтов и 32766 кодовых единиц UTF-16. Относительные пути отсчитываются от рабочего каталога процесса, который может отличаться от каталога исходника. Абсолютные пути и пространства имён ОС используют права учётной записи и файловой системы интерпретатора или сгенерированной программы. Песочницы корня проекта, ограничения только обычными файлами и тайм-аута чтения нет.

Предел задаёт максимальную длину возвращаемых данных, а не запрос усечённого префикса. Пустой файл успешно читается при нулевом пределе. Превышение даёт ошибку 5 без частичного значения bytes. Хранилище растёт геометрически по мере чтения; весь запрошенный предел заранее не выделяется. Финальное пробное чтение одного байта отличает EOF ровно на пределе от превышения. Чтение может наблюдать одновременные изменения файла и не гарантирует атомарный снимок объекта файловой системы.

`buffer(limit)` создаёт пустой изменяемый буфер. Нулевой неотрицательный предел допустим. `append_byte` добавляет один байт, если позволяют предел и ресурсы; отклонённый байт или исчерпанный предел не меняют содержимое. Значение вне 0..255 даёт ошибку 7. `len` и индексация только для чтения работают с bytes и buffer; прямого присваивания элементу нет. Копирование, передача и возврат buffer создают ссылки на тот же стабильный объект, в том числе после роста хранилища. Неизменяемый параметр или привязка match запрещает переназначение, но не изменение через `append_byte`. `snapshot` копирует текущие данные в независимое неизменяемое bytes; последующие изменения буфера не затрагивают копию. Копирование привязки bytes разделяет неизменяемые данные, а не копирует их содержимое.

Динамические bytes, buffer и успешные полезные значения результатов используют автоматический подсчёт ссылок. Ссылки действительны при переназначениях, вызовах/возвратах функций и выходах из областей, пока существует хотя бы одна ссылка. Хранилище освобождается после последней ссылки; очистка исполнения также освобождает оставшиеся отслеживаемые объекты после фатального выхода. Байтовые литералы существуют всё время программы. Открытых адресов, явного освобождения и универсального API выделения памяти нет.

`result<bytes>` и `result<buffer>` содержат полезное значение успеха либо целочисленный код ошибки. `status` содержит успех без полезного значения либо целочисленный код ошибки. Результаты и status можно хранить, присваивать при совпадении типа, передавать функциям и возвращать. Их нельзя использовать как bool, индексировать, выводить или неявно раскрывать. Пользовательских конструкторов успеха/ошибки, других типов полезного значения result, вложенных результатов и синтаксиса исключений нет.

```text
match read_file(bytes("input.bin"), 1048576) {
    ok(data) {
        print(len(data))
    }
    err(code) {
        print(code)
    }
}

match buffer(2) {
    ok(output) {
        match append_byte(output, 255) {
            ok { print(output[0]) }
            err(code) { print(code) }
        }
        match snapshot(output) {
            ok(copy) { print(len(copy)) }
            err(code) { print(code) }
        }
    }
    err(code) { print(code) }
}
```

`match expression { ... }` вычисляет выражение результата/status один раз. Каждый match содержит ровно две ветви в таком порядке: `ok(name) { ... }` для полезного значения result либо `ok { ... }` для status, затем `err(code) { ... }`. Обе ветви обязательны, даже пустые. Подстановочного шаблона и других образцов нет. Все ветви статически проверяются, исполняется только выбранная. Привязки полезного значения и кода ошибки неизменяемы и видимы лишь в своей ветви; затенять видимое имя нельзя. Код ошибки имеет тип int64. Каждый match добавляет один уровень управления в общий предел if/while; каждая привязка ветви учитывается в общем лимите статических привязок. Возвраты из обеих ветвей могут обеспечить путь возврата функции. `ok` и `err` являются контекстными именами ветвей, а не глобально зарезервированными ключевыми словами.

Эти восстанавливаемые коды операций являются значениями для обработки через `match`, а не кодами завершения процесса или фатальными ошибками A0401/A0402/A0403:

| Код | Значение |
| --- | --- |
| 1 | Недопустимый аргумент: некорректный/пустой/содержащий NUL/слишком длинный путь или отрицательный предел |
| 2 | Файл или путь не найден |
| 3 | Доступ или совместный доступ запрещён |
| 4 | Другая ошибка открытия, чтения или закрытия |
| 5 | Превышен предел длины объекта, живого хранилища или числа живых объектов |
| 6 | Не удалось выделить память |
| 7 | Добавляемый байт вне 0..255 |

Обработанная ошибка сама по себе не останавливает исполнение и не задаёт ненулевой код завершения процесса. Арифметические ошибки и выход индекса за границы при вычислении аргументов сохраняют обычные фатальные правила. Пути и отрицательные пределы проверяются до открытия файла; предел выше максимума объекта даёт ошибку 5. `append_byte` проверяет диапазон байта до проверок роста и предела.

Пределы управляемой памяти: 16 МиБ (16777216 байтов) на динамический объект, 64 МиБ (67108864 байта) живого хранилища дескрипторов и полезных данных, 4096 живых динамических объектов. Каждый дескриптор занимает 64 байта. Учитывается выделенная ёмкость, а не только длина; рост проверяет пик при одновременно живых старых и новых данных, а snapshot требует места для независимой копии. Освобождённые объекты возвращают бюджет памяти и числа объектов. Это не пределы общего RSS процесса, накладных расходов аллокатора/ОС, буферов исходника, промежуточных данных компилятора, исполняемых образов, временного пути, времени, числа итераций или всего ввода-вывода. Преобразование пути Windows может временно выделить до 65534 дополнительных байтов вне управляемого учёта.

## Логические значения, сравнения и условия

`true` и `false` имеют тип `bool`. Арифметика и унарные знаки требуют `int64`. Сравнения порядка `< <= > >=` требуют два целых и возвращают bool по знаковому порядку. Равенство `== !=` принимает два значения одного скалярного типа: int64/int64 или bool/bool. Строки не сравниваются. Bool и int64 не преобразуются друг в друга неявно.

Операторы сравнения и равенства ассоциируются слева на своих уровнях приоритета. `1 < 2 == true` означает `(1 < 2) == true`. Цепочки сравнений в стиле Python не поддерживаются: `1 < 2 < 3` отклоняется, потому что второе сравнение получает логический операнд. `!` требует bool и отрицает его. `&&` и `||` требуют логические операнды и вычисляются слева направо с сокращением: ложная левая сторона AND или истинная левая сторона OR пропускает всю правую часть, включая вызовы, вывод и арифметические ошибки. Обе стороны всё равно полностью разбираются и статически проверяются, поэтому `false && unknown` является ошибкой. Константное `false && (1 / 0 == 0)` допустимо, но `false && runtime_value` не является допустимым инициализатором константы.

```text
var price = 120
var expensive = price > 100
if expensive {
    price = price - 20
    print(price)
} else {
    print(0)
}
print(true == false)
```

Условие должно иметь тип bool. Круглые скобки вокруг него являются необязательной группировкой выражения; фигурные скобки ограничивают блоки, отступы не имеют грамматического значения. Открывающая скобка может стоять после условия на той же строке либо после переводов строки и комментариев. Ключевого слова `end` нет. Если `else` присутствует, оно следует за закрывающей скобкой then-блока с возможными промежуточными переводами строки и комментариями и вводит новый блок либо условие `if`. Переводы строки после `else` допустимы. Цепочка `else if` проверяет условия по порядку до первой истинной ветви, иначе выполняет завершающий `else`, если он есть. Каждая ветвь имеет отдельную лексическую область; цепочка расходует ограниченную глубину управления так же, как вложенные условия.

Обе ветви полностью разбираются и проверяются до любого исполнения и вывода, включая неверные инициализаторы констант в невыбранной ветви. Во время исполнения условие вычисляется один раз, затем выполняется только выбранная ветвь. Ошибка времени исполнения в невыбранной ветви не происходит. Предыдущий успешный вывод и порядок ошибок проверяемой арифметики сохраняются.

Внутри блока `=` обновляет уже видимую изменяемую привязку. `var` и `const` объявляют новые локальные привязки блока и отклоняют имена, уже видимые в любой внешней области. Локальные имена исчезают у закрывающей скобки. Соседние блоки могут независимо объявлять одинаковые имена в разных ячейках. Имя, введённое только внутри ветви, недоступно после неё, даже если обе ветви используют одинаковое написание. Все привязки инициализируются до использования; каждое объявление в обеих ветвях учитывается в общем пределе. Присваивания не расходуют новые ячейки привязок.

## Циклы while

```text
var count = 0
var total = 0
while count < 5 {
    var next = count + 1
    total = total + next
    count = next
}
print(total)
```

Программа выводит `15`. Условие должно иметь тип bool и вычисляется перед каждой итерацией, включая первую. Ложное условие пропускает тело. Круглые скобки являются необязательной группировкой; открывающая фигурная скобка может стоять в строке заголовка или после переводов строки и комментариев. `end` не используется. У `while` нет части `else`.

Всё тело разбирается и проверяется до исполнения, даже для `while false`. Неизвестные имена, неверные типы и инициализаторы констант в недостижимом теле являются статическими ошибками. Ошибки времени исполнения происходят только в вычисляемых условиях или исполняемых инструкциях и сохраняют прежние эффекты. Изменённая внешняя переменная повторно читается в следующем условии.

Тело имеет лексическую область видимости. Существующие изменяемые привязки можно обновлять; новые локальные привязки не выходят за пределы тела. Локальные изменяемые объявления выполняют свои инициализаторы на каждой итерации. Константы вычисляются при проверке. Каждое объявление занимает одну статическую ячейку привязки независимо от числа итераций. Вложенные циклы, условия и match используют общий предел глубины блоков. Управление циклом не увеличивает стек на каждой итерации; операции тела могут выделять и освобождать динамические объекты. Ограничения числа итераций или автоматической гарантии завершения нет; `while true {}` работает до внешней остановки. `break`, `continue` и `for` не реализованы.

## Функции

```text
const digit_min = 48
const digit_max = 57

fn is_digit(code: int64) -> bool {
    if code < digit_min {
        return false
    }
    return code <= digit_max
}

print(is_digit(47))
print(is_digit(53))
```

Результат: сначала `false`, затем `true`. Функции объявляются только на уровне файла. Сигнатура задаёт от нуля до шестнадцати параметров и явный тип результата; каждый тип: `int64`, `bool`, `bytes`, `buffer`, `result<bytes>`, `result<buffer>` или `status`. Имена типов контекстные; `bytes` и `buffer` также являются зарезервированными встроенными именами. Списки параметров допускают переводы строки между элементами и после запятых; имя параметра, двоеточие и полный тип остаются на одной строке. Завершающая запятая отклоняется. Открывающая скобка тела может следовать за типом результата после переводов строки и комментариев; законченное определение требует перевода строки или конца файла. Специальной входной функции нет: инструкции уровня файла выполняются по порядку, определения пропускаются.

Вызовы используют круглые скобки и выражения, разделённые запятыми. Они могут находиться в инициализаторах, присваиваниях, условиях, выводе, возвращаемых выражениях и аргументах других вызовов. Аргументы вычисляются слева направо, затем значения параметров копируются до запуска тела. Число и типы аргументов должны точно соответствовать объявлению. Вызов без аргументов записывается `name()`. Отдельные вызовы с отброшенным результатом, значения функций, вложенные определения, замыкания, перегрузки, параметры по умолчанию и результаты void не поддерживаются. `print` является зарезервированной инструкцией вывода с той же формой аргументов в скобках; его нельзя использовать как результат выражения.

Привязки параметров являются неизменяемыми значениями времени исполнения, а не константами времени компиляции. Присваивание параметру даёт A0305; ссылка на него в инициализаторе `const` даёт A0306. Для изменяемой локальной копии используется `var local = parameter`. Вызовы являются операциями времени исполнения даже с литеральными аргументами и не могут инициализировать константу времени компиляции. Арифметические ошибки и прежние эффекты сохраняют обычный порядок.

Каждое тело имеет собственную локальную область и не может читать изменяемые значения уровня файла или локальные значения другого вызова. Более ранние константы времени компиляции уровня файла доступны; их значения встраиваются без захвата времени исполнения. Константы, объявленные после функции или внутри ветви уровня файла, не видны. Параметры и локальные значения не могут затенять видимые более ранние константы. Имя невидимого изменяемого значения уровня файла можно использовать локально. Имена функций зарезервированы против объявлений привязок по всему файлу; вызовы могут ссылаться на функции, определённые позже.

`return expression` немедленно выходит из функции и должен соответствовать типу результата. Возврат вне функции, неверная сигнатура, несовпадающее число аргументов или отсутствующий путь возврата дают A0308. Несоответствие типа возвращаемого значения даёт A0303. Каждый путь, который может достичь конца тела, должен возвращать результат: `if` или `match` гарантирует возврат только при возврате из обеих ветвей, а цикл консервативно считается способным завершиться, включая `while true`. Недостижимые инструкции и тела неиспользуемых функций всё равно проверяются. Прямые и косвенные рекурсивные графы вызовов, включая недостижимые рекурсивные вызовы, дают A0309.

Сигнатуры функций проверяются до основного прохода по инструкциям, затем тела функций проверяются в порядке определения. Из-за этого порядка семантическая ошибка уровня файла может сообщаться раньше ошибки тела, расположенного выше в исходном тексте. Все проверки завершаются до исполнения и создания выходного файла. В этом подмножестве вызовы не пересекают границу внешних функций или экспортируемых модулей.

## Ограничения и диагностика

Пределы: 256 статических привязок суммарно, включая параметры, объявления и привязки ветвей match во всех телах функций; 64 функции; 16 параметров или аргументов вызова; 64 активных уровня if/while/match на тело; 128 уровней группировки, вызовов, индексов и унарных операторов выражения; 128 одновременно живых постфиксных операндов. Тело функции не расходует уровень управления; скобки сигнатуры не являются вложенностью выражения. Круглые скобки выражения учитываются, в том числе сразу после `print`. Каждый унарный оператор добавляет уровень, включая минус непосредственно перед литералом. Плоские левоассоциативные бинарные цепочки не добавляют глубины группировки. 257-я привязка или 129-й живой операнд дают A0307; чрезмерная вложенность выражения даёт A0202. Пределы функций, параметров и аргументов проверяются до доступа к ограниченному хранилищу.

Совокупная модель стека вызовов генерируемого ABI ограничена 64 КиБ, включая основной код, вложенные вызовы, адреса возврата и вспомогательные функции. Динамический runtime может добавлять два вспомогательных кадра по 168 байтов с адресами возврата, то есть запас 352 байта. Каждый сгенерированный кадр меньше 4096 байтов и затрагивается при входе. Ациклический граф проверяется даже для неиспользуемых функций. Это консервативная политика ресурсов сгенерированного кода, а не измерение точного использования стека интерпретатором на C или внутренними операциями API ОС.

Порядок: полная проверка UTF-8, всех CR, лексический анализ, полный синтаксический разбор, затем описанные выше проверки сигнатур, основных инструкций и тел, проверки путей возврата, графа вызовов и ресурсов. Внутри тела каждое имя назначения или вывода и предел объявлений проверяются до постфиксного выражения, затем проверяется итоговый тип. Условие if/while проверяется до его блоков; нелогическое условие даёт A0303 на корневом токене выражения. Константная арифметика использует тот же семантический проход. Статическая ошибка предотвращает исполнение и создание исполняемого файла.

A0201 указывает токен, нарушающий грамматику. A0202 указывает чрезмерную группу, унарный знак или открывающую фигурную скобку. 65-й активный блок даёт A0202 на своей открывающей скобке; группы и унарные операторы сохраняют отдельный предел 128 уровней. Проверки имён и типов указывают соответствующее имя, число или оператор; неверный итоговый тип объявления указывает имя назначения. Для отрицательного литерала диапазон A0304 включает только цифры. Статические ошибки содержат файл, строку, столбец, стабильный код диагностики, сообщение, ограниченный фрагмент исходного текста с указателями и контекстную подсказку, где она применима. Некорректный UTF-8 сообщает смещение в байтах. Диагностика времени исполнения сохраняет точный формат ниже.

Для неизвестной переменной или функции сообщение цитирует имя. Вариант написания предлагается только при единственном близком кандидате подходящего вида, видимом в данной точке; короткие имена, неоднозначные совпадения, имена вне области видимости и далёкие догадки подсказку не получают. Диагностика никогда не объявляет имя молча. Управляющие символы и скалярные значения вне ASCII экранируются во фрагментах для однозначного выравнивания указателей и безопасности терминала; это меняет только отображение, а не интерпретацию исходного текста.

Коды завершения: 0: успех; 1: статическая ошибка исходного текста; 2: ошибка инструмента или ввода-вывода; 3: арифметическая ошибка или выход индекса за границы при исполнении. Runtime stderr содержит точно `A0401: int64 overflow.`, `A0402: division by zero.` или `A0403: byte index out of bounds.`, затем LF, без пути и позиции. Неудачная запись диагностики может оставить префикс, но сохраняет код 3. Неудачная запись stdout может оставить частичный вывод и останавливает исполнение с кодом 2.

## Границы реализации

Текущий компилятор и интерпретатор используют C11; собственный генератор Altai создаёт AMD64 для Windows x86-64. Модули, числа с плавающей точкой, массивы, строковые переменные, рекурсия и универсальное выделение памяти отсутствуют. Квадратные скобки поддерживают проверяемую индексацию bytes/buffer только для чтения; добавление байтов доступно через `append_byte`. [Контракт машинного кода](native.md) описывает цели, устройство и обработку файлов. Лексер и компилятор не реализованы на собственном языке; вспомогательные классификаторы символов на Altai не являются полным лексером Altai.
